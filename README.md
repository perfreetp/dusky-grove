# 冰裂缝 · 滑轮救援实验

一套可以拖动、可以把玩的绳索力学场景：冰裂缝口架着救援滑轮，缝隙下方是被困者，右上是救援队。
切换不同的滑轮组，加重配重，观察**绳速比**和**摩擦**怎样一起把提升拖到停滞。

打开 `index.html` 即可（无需构建）。本地起服务：`npm start` → <http://localhost:8080/>。

## 怎么玩

- **拖动滑轮**：裂缝口那块滑轮组可以拖，动滑轮（挂在人身上的那个）也能拖。绳子的走向会跟着变，
  包角随之改变——包角越大，弯曲损耗越重。
- **切换滑轮组**：单滑轮 1:1、双滑轮 2:1、带抓结滑轮组 3:1。绳速比立刻按倍率变化，
  配重速度同步变成绳速 ÷ 倍率。
- **按住拉绳**：按住按钮或空格键拉绳；松开就停。也有「自动」模式，一直拉到停滞为止。
- **加重**：拖重量滑杆或点 +/−。一级一级加重，看哪一种滑轮组先拉不动。
- **自动测完三组对照**：用同一套物理模型把三组各测一遍，结果填进「停滞记录」并画出对比条。

## 画面里读到什么

| 读数 | 含义 |
| --- | --- |
| 绳速比 | 绳走过 1 m 与配重升高之比，由绳股几何算出（名义 1/2/3） |
| 有效倍率 | 扣除摩擦之后真正到手的倍率 = 绳速比 ÷ 摩擦总增益 F |
| 所需拉力 | 把配重拉起来时手上要出的力，越过 1500 N 就拉不动 |
| 接触点摩擦 | 每处滑轮/抓结各自吃掉的力，包角越大吃得越多 |
| 绳段温度 | 摩擦功率把绳段烤热，越过阈值变红，并且更咬绳 |

## 物理模型（`physics.js`，纯函数、可无头测试）

**倍率**只由拓扑决定：几股绳兜住动滑轮，绳速比就是几。

    v_load = v_rope / n

**摩擦**沿绳从负载往手上逐段传递，两类机制叠加：

- 滑轮：轴承损耗 + 绳索弯曲滞后损耗，两者都随包角、绳速与重量增大
  （`T_out = T_in · (1 + k_bear + k_hyst·(θ/π)^1.5) · mf`）
- 抓结：滑动摩擦，按欧拉-埃特尔魏因关系 `T_out = T_in · e^{μθ}`，是全系统最烫的点

`mf` 随绳速（v^1.4）、随重量、再随自身热度增大。于是：

    F     = 所有接触点比值的乘积
    R_req = m·g·F / n
    速度因子 = 在 R_req 逼近 R_MAX 时平滑衰减

倍率与摩擦始终同时参与：倍率决定「配重速度 = 绳速/n」，摩擦决定「这个绳速你举不举得动」。
绳被拖得越慢，摩擦生热越少；一旦被加重到只剩蠕动，抓结仍在打滑研磨，热量反而继续累积，
热绳更咬——这就是重载下提升会先「顿住」再彻底停滞的原因。

**停滞**：所需拉力越过队伍上限（1500 N）时，负载速度降到 0，界面给出停滞横幅，
并点名**摩擦最重的绳段**（以及最烫的那一段）。同样的模型也用于「自动测完三组对照」。

### 几何（`riggeom.js`）

绳路的折线、每处的包角、以及由绳股与竖直方向夹角算出的实际绳速比都在这里。
所以拖动滑轮真的会改摩擦，而不是只改画面；把动滑轮拖偏，绳股不再竖直，倍率也会略低于名义值。

### 验收

    npm test       # 物理模型的无头断言：倍率、摩擦随速度/重量增长、发热、停滞次序
    npm run verify # 用 Chromium 驱动页面：切组、拉绳、拖动滑轮、加重、对照测量

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架与面板样式；按顺序加载脚本，Pixi 不可用时回落到 Canvas 2D |
| `main.js` | PixiJS 场景：裂缝剖面、绳索、滑轮、被困者、救援队、交互与 HUD |
| `physics.js` | 纯模型：倍率、摩擦、发热、停滞，可在 Node 中直接跑 |
| `riggeom.js` | 纯几何：绳路折线、包角、几何绳速比 |
| `shim.js` | 极小的 PixiJS 兼容层（Canvas 2D），离线时页面照常工作 |

滑轮画成圆形，绳索以折线表示走向，绳速比与摩擦始终同时参与每一次采样计算。
